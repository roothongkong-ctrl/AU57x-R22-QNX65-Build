# R04｜电信专用网络模式候选策略（只限云端仿真）

车型：2017 Audi A6L C7，MHI2_CN_AU57x_K1006_2 / MU1005。

## 完成内容

- 基于原厂 NAD 的四种 AT+COPS 模板，独立编写纯 C 研究模拟器，输出字符串、不调用原厂服务、不会发送 AT 指令。
- `telecom/qnx/ct_network_policy_sim.c` 针对电信 46003 / 46005 / 46011 做一种**未经实车证实的**模式假设：当 manual=true 且 OEM mode=1 时，从 `AT+COPS=1,2,PLMN,0` 改为 `AT+COPS=1,2,PLMN`。
- 46012 不属于此证据确认的电信列表，必须保持原样；中国移动 46000 / 46002 / 46007 / 46008、联通 46001 / 46006 均不改变；自动选网所有分支都保持原样。
- 字符串模拟之外的真实 modem 选网行为、实际运营商支持、网络注册结果全部未知。

## 可复验编译和测试

- 云端 Linux GCC 独立构建，`telecom/tests/test_qnx_policy_host.c` 覆盖电信/移动/联通保持边界、非法输入和缓冲区溢出拒绝。
- 最新 host-policy CI 已运行通过 33 项纯 C 用例（GitHub run 44933653525）。
- 在同一 workflow 中另启动真正 QNX6.5 ARMv7 toolchain Docker 构建，使用项目已有 ELF ABI 门禁；必须看 QNX native job 的最终结论才能称编译通过。
- 无任何原厂二进制参与公开 CI；编译输出即使成功也只是 .so 研究样品，**未接入原车任何入口**，不具备安装价值。

## 不允许跳过的阻塞

1. 尚未证明中国电信 SIM 会把内部 mode 设为 1；如果其实际 mode!=1，此假设完全无效。
2. 仅手动选网路径构造不同；原车主要使用自动选网，尚未确认自动路径影响。
3. 真实车上的 Nadia/NAD 所选 Huawei/Cinterion 硬件型号、当前 LTE 注册状态、拒绝码未知。
4. 未获得稳定、可回滚的 OEM 连接点；没有任何真实修复补丁。
5. 移动/电信真实通信功能未测试。云端绿色状态不能满足车机安装放行。
