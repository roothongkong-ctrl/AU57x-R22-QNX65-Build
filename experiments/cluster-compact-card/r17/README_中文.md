# R17：已把112卡片视频的解码器接进MIB v1.2.14原版播放器（源码实验）

**目标**：奥迪 A6L C7 机械仪表原版高德白色导航提示卡片缩小到70%，地图位置/比例/像素不变。当前未验证真实高德/实车。

## 这次完成的真实修改

`patch_real_player.py` 严格只改官方 `player/opengl_gpu.cc` 三处：
1. 可选引入112独立解码sidecar与R12/R14源码；
2. 在主播放器启动时按**编译宏 + 环境开关 + 只限CarPlay --no-ack本地111源 + 800×298窗口**决定是否启动112（否则原播放器完全不受影响）；
3. 在原111视频解码器完成YUV420三平面拷贝**之后**、原有 `g_framePool.publishWrite()` **之前**，把111纯地图帧提交R12，与112白色卡片帧同步后按70%合成。无112、超时、尺寸错、解码失败时不动111原始帧。播放结束先等111解码退出，再关闭112线程。

`r17_card_sidecar.h`：使用独立线程连接R16已新增的**127.0.0.1:19822**，收到来自R13真实AirPlay接收线程的**H264 Annex-B**后，经R14 FFmpeg解码并输入R12。丢失连接立即禁用卡片叠加。

`test_player_sidecar.cpp`：以真实编码H264数据和本地TCP连接测试卡片叠加及111地图其余YUV像素完全不变，含断线/格式错误/禁止模式。

## 严格区分已实现与未验证

- **真实源码接入播放器**并不等于高德会发送112号独立视频。苹果的示例并未证明高德兼容，最终要取得真实iPhone协商/视频或实车验证。
- **R9的卡片矩形170,12,350,118只是合成测试数据**，不是高德真实卡片自动识别坐标。真实卡片大小、位置与在112视频上的呈现形式尚未确认。
- 当前只对**实际解码尺寸为800×298**的地图帧进行合成；实际iPhone请求/视频若为1010×376、800×480或其他，直接回退，不做拉伸或裁切，也不称“完成”。
- FFmpeg 112码流解析、111/112帧配对按接收端MONOTONIC时间，静态卡片更新若超过200毫秒停止叠加，避免过时导航信息；实车是否影响使用尚未测。
- QNX ARM和车机内存性能、GPU/原导航显示恢复、安全备份尚无完整验证，**此版本不能用于实车安装**。
