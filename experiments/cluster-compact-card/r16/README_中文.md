# R16 / 实际112视频到70%合成器：本地H.264传输接通（源码实验）

**目标未变：原版高德白色导航卡片缩至70%，地图不动，中控不动。**

这轮在 R15 分支上真实新增：
- `r16_card_tee.h`：复用MIB官方的 `alt111_video` 内核，把AES解密、AVCC校验后的112 H264转换为Annex-B，只向 **127.0.0.1:19822** 本地消费者发送；不改110/111，不写视频文件；非阻塞、有限内存队列、断开自动清除。
- `r13_112_probe.inc`：将R16本地112输出接入R13 **真实CarPlay 112接收线程**。只有构建宏 `CLUSTERMAP_R16_112_TEE_LAB` 与运行环境 `CLUSTERMAP_R16_112_TEE=1` 均打开才启用。R13自身也须双重实验开关；所有正常安装无这项功能。
- `test_tcp_to_r14.cpp`：GitHub用FFmpeg真正编码测试视频，提取SPS/PPS/IDR，把AVCC传入MIB原版内核，经过127.0.0.1 TCP送给R14真实FFmpeg解码，再交R12输出70%卡片，并逐像素比较卡片之外的地图**一字节不变**；也测试断链/旧会话回退。

## 现阶段不能宣称的事情

- GitHub采用**自己生成的H.264测试视频**，没有真实高德iPhone发送112的证据。
- 本次112本地端口已从真实R13接收层接出来，但目前**尚未把实际车机 `player/opengl_gpu.cc` 的111解码画面与112解码画面接成同一显示线程**；R14在测试程序里运行。
- MIB v1.2.14实车可能提供的111视频是1010×376再适配到800×298仪表；R12/R14测试夹具固定为800×298，**需解决画面尺寸/时间戳配对，不能直接宣称上线**。
- R15修改111向iPhone索取map-only，同时112索取instructioncard，但**iOS高德是否都接受并非编译能证实**。
- QNX ARM构建、原车安装、备份恢复仍未完成。不提供刷车安装包。
