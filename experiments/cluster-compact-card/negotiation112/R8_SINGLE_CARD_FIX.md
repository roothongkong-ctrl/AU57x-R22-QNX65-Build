# R8 单张原版高德卡片，真正的恢复缺陷修复

基线：MIB Cluster Map v1.2.14 / AU57x K1006_2。此独立实验不改装车原软件，不产生安装包。

## 本次修复了什么
R6 的 n112_receive_one() 在发生非法视频包/校验错误时会调用 c112_end()，导致此前存放在 c112_receiver 内的加密回调被清空。下一次 n112_setup() 从已清空的对象取回调，无法重新建立112视频会话。修复方式：把当前 CarPlay 会话自己的解密回调和上下文存到 n112_session 内，断开112后不会消失，之后的合法 SETUP 可重新获取。

用户只要一张卡片：增加严格门槛，必须把111的初始内容选择为 maps:/car/instrumentcluster/map（**纯地图**），才允许112声明为 maps:/car/instrumentcluster/instructioncard（**原版卡片**）。如果111仍是默认组合画面，拒绝启动第二卡片，否则会出现“双卡片”。

## 测试
R8 对现有112 TCP接收、原v1.2.14 H264解析器、300次正常断开重连，再新增250次非法包断开与重连，随后再次收到合法视频包，并在每次确认原111地图状态不变。CI用20项既有测试矩阵不同编译配置回归。

## 必须区分
模拟设置支持112绝不证明真实iPhone/高德发送112。Apple允许使用两个仪表显示流，但112在本机尚无真实连接、原生AES和QNX ARM运行验证；而第三方导航APP是否输出原版卡片尚不确定。本次没有向真实CarPlay宣布112，没有修改官方包。离上车安装仍有实际收发和解码验证。
