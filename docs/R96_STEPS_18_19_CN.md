# R96｜第18、19步连续开发实绩（2026-11-23）

**适配目标**：2017 A6L C7 PA、MHI2_CN_AU57x_K1006_2 / MU1005，QNX 6.5 ARMv7。

## 本轮实际完成（离线范畴）

### 第18步：一键安装与自动恢复的主机实验实现

- 在已验证的 R95 SHA256/权限/所有权固定清单基础上，新建 `tools/r96_oneclick_codegen.py`，生成真实 C `txn_spec` 和 `supervisor_fixture.c` 生命周期函数驱动的测试可执行程序。
- `oneclick` 顺序：独占维护锁 → 检查原文件和候选 SHA256 → 停止旧测试服务 → 持久备份 → 原子替换 → 启动候选测试进程 → 获得健康信号 → `COMMITTED`。
- 失败恢复：候选启动失败、健康检查失败、超时、进程异常退出、原件或候选篡改均进行实际文件恢复或拒绝改写。`restore` 显式恢复；`boot` 再次健康检查失败恢复旧文件。测试并非只改一个状态标志。
- 整个生成入口继承 R95 的 `au57x-r95-*` 专用实验目录和 `.R95_HOST_FIXTURE_ONLY` 标记，生成结果只接受**主机模拟生命周期**，**没有原厂 QNX 5F 停止/启动权限、原厂 MFi 密钥、原厂启动器或车辆挂载目录**。
- 因而完成的是 `STEP18_OFFLINE_HARNESS`，不是车机生产安装器。生产接入需要可信原厂回调、真实车机路径/分区、fsync 和开机自恢复验收。

### 第19步：完整源码复核包与上车前门禁

- `tools/r96_candidate_bundle.py` 生成确定性 ZIP，内含 R95 第3～17步测试证据、R96 缺口清单、中文说明、带 SHA256 的 `manifest.json`。只允许 `.md/.json/.txt` 证据文件。
- 与已有 `tools/sd_package_audit.py` 联合，对重复成员、路径穿越、符号链接、额外执行脚本、冒充可安装状态、清单不符采取拒绝策略。
- R96 整包同时保留 R45/R44/R87/R85 + R95/R96 代码、C 恢复引擎、测试与版本日志。**本次交付的是完整“离线研发源码复核候选包”，不等于“完整装车安装候选包”。**
- R96 所有测试都可以不碰汽车完成。不存在预填车机未知原始配置的强制安装脚本。
