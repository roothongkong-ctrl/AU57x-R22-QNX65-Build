# MU1005 原厂 OSAPI 事件线程（NO INSTALL）
从用户历史 Round24 Offline ZIP 恢复三个原厂库，SHA256 与 2026-11-12 记录一致：libcomm.so 823296 2eb1d8550c3ad4a8cbdafba567168189dc2cb195d1f4b12b0661afe1a19b12a8；libosal.so 520192 20345734f469d8a09bb0e8e3ca2d7b4cecfa915308353ee91d230a37c104de11；libutil.so 950272 589d575060d76b7c71c2f964e5f94e9e5c8d35be1fb13f7ab3e7eb7e627a69f0。实际使用 PT_DYNAMIC、DT_HASH、DT_SYMTAB、JMPREL 和 ARM PLT 解析，配合反汇编，不依赖已剥离的节表。三个库的地址均为各自 ELF VA，不是运行时固定地址。原厂二进制不提交。
- btstack 0x279c40 构造名称 OSAPI 的 244-byte ActiveObject；0x27a1e4 取 OSAPI+0x3c factory，0x27a200 虚调用取共享对象，0x27a300 调 enque。factory vtable 0x2c1098，slot+8=0x278484（复制 factory+4 的 SharedPtr，对象指针 +8）。
- libcomm enque 0x4e620：0x4e654 pthread_mutex_lock(AO+0xc8)，0x4e6b8 unlock，0x4e6c8 pthread_cond_signal(AO+0xd0)。threadLoop 0x4e9bc：0x4ea0c 锁，0x4ea74 解锁，0x4eab4 事件虚调用，0x4eae4 重取锁。队列锁释放不代表 SDK OSAPI+4 锁释放。0x4d878 将 AO+8 转为 osal::Thread，0x4d87c 调 getThreadId；libosal 0x3b61c 读 this+0x18，合成 AO+0x20；0x3b7b0 调 pthread_self。libutil RunnableWrapper 0x51688 取原 runnable，0x516a0 虚调用。原厂 pthread_create 调用 0x3c0f4。libcomm AO vtable 0xc69a0，地址点 +8，需真实 load bias。
- libosal MutexOps::init 0x3f5e8：r1 选择 pthread_mutexattr_settype 的 2/3，r2 控制 pthread_mutexattr_setprotocol，r3 控制 pshared；btstack SDK 三个锁 init 传 (1,1,0)，AO 队列锁 init 传 (0,0,0)。未核实目标 libc 数值常量，不将 2 直接宣称为可任意递归；更不把队列线程匹配等同于 iAP2 回调安全。
- 新增 mu_bt_osapi_thread_matches，双读原厂 OSAPI/factory/AO 身份、线程 ID、启动/停止状态；独立真实映射与读取 provider 仍必需。仅作为联合 ARM 库可调用的只读身份检查，不自动 hook，不代替原 owner 证明。主机 mock 测试通过（错误 tid、错误 bias、状态变化、读失败）。
